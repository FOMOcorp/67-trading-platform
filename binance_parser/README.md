# Binance Spot Dataset

**Назначение:** собрать исходные данные для прогноза спотового BTC.
Основной рынок — Binance Spot. OI и фактический funding perpetual используются
только как дополнительный контекст. Данные бесплатные, API-ключ не нужен.

**Стандартная загрузка: `spot,metrics,funding`.**
Фьючерсные торговые свечи, mark/index/premium, разница цен, long/short ratios,
ликвидации и стаканы в основной датасет не входят.

## Запуск истории

Python 3.10+, дополнительные библиотеки для истории не нужны. Из этой папки:

```powershell
python history.py --start 2021-09-01 --end 2026-11-15 --output data/history_5y
```

Начало включается, конец не включается. Даты — UTC.
После скачивания автоматически создаётся **один обычный CSV**:

```text
data/history_5y/BTCUSDT_dataset_1m.csv
```

Вручную объединять файлы не требуется. Для нескольких `--symbols BTCUSDT,ETHUSDT`
создаётся по CSV на символ. Дополнительные символы автоматически не скачиваются.

После обрыва повторите ту же команду. Готовые части проверяются по SHA-256,
заново не скачиваются. Windows-блокировки при замене файлов обрабатываются
ограниченными повторными попытками. Один процесс на выходную папку.

При переходе со старой версии завершённые spot/OI/funding сохраняются.
Ненужные источники исключаются из плана, их прежние файлы не удаляются;
старые записи прогресса сохраняются в `retired_entries`.

Если загрузка уже запущена старой версией, остановите её через `Ctrl+C`
и повторите команду: работающий процесс сам обновление кода не подхватывает.

## Что находится в итоговом CSV

Одна строка — одна скачанная **спотовая минута**. Цены и объёмы сохраняются
с исходной десятичной точностью. Недостающие спотовые свечи не придумываются.

| Поля | Содержание |
| --- | --- |
| `timestamp`, `datetime_utc` | Начало минуты, Unix milliseconds и UTC |
| `available_at` | Конец минуты — момент доступности завершённой свечи |
| `symbol` | Например, BTCUSDT |
| `open`, `high`, `low`, `close` | Исходные спотовые цены |
| `volume_base`, `volume_quote` | Общий спотовый объём в BTC и USDT |
| `taker_buy_base_volume`, `taker_buy_quote_volume` | Агрессивные покупки в BTC и USDT |
| `taker_sell_base_volume`, `taker_sell_quote_volume` | Агрессивные продажи в BTC и USDT |
| `number_of_trades` | Общее количество исполнений |
| `trade_imbalance` | `(buy − sell) / total`, пусто при нулевом объёме |
| `last_trade_id` | Пусто: Binance klines не содержит ID последней сделки |
| `open_interest_base`, `open_interest_quote` | OI perpetual в базовом активе и USDT |
| `oi_timestamp`, `oi_age_seconds` | Время и возраст последнего наблюдения OI |
| `funding_rate` | Последняя известная фактическая ставка начисления |
| `funding_timestamp`, `funding_age_seconds` | Время и возраст начисления |

Продажи рассчитываются как общий объём минус taker buy; используется Decimal.
У любой сделки есть обе стороны: taker buy означает, что инициатором был
покупатель, исполнивший выставленную продажу. Это не число покупателей.

## Объединение OI и funding со спотовыми минутами

Для каждой строки используется последнее событие **не позже закрытия минуты**.
Будущие наблюдения не подставляются. Биржевое время события не гарантирует
момент его публикации — это нужно учитывать при обучении.

Пределы свежести теперь явные и настраиваемые:

| Параметр | Значение по умолчанию |
| --- | --- |
| `--oi-max-age-minutes` | 15 минут |
| `--funding-max-age-hours` | 24 часа |

При превышении предела значение остаётся пустым, время и возраст последнего
наблюдения сохраняются. `0` отключает соответствующее ограничение.
Выбранные настройки записываются в `.csv.metadata.json`. Исходные события
в дневных файлах не изменяются.

```powershell
# Пересобрать CSV из уже скачанных данных без интернета.
python history.py --output data/history_5y --csv-only

# Пример явного отключения ограничений возраста при пересборке.
python history.py --output data/history_5y --csv-only --oi-max-age-minutes 0 --funding-max-age-hours 0
```

Калман, RSI, MACD, Bollinger, momentum, VWAP и таргет в парсере не рассчитываются:
это последующий этап подготовки признаков. Сырые цены не сглаживаются.

## Покрытие и источники

Spot загружается из месячных/дневных ZIP Binance с проверкой официального
`.CHECKSUM`; недоступные архивы свечей дополняются публичным REST.
Микросекунды spot-архивов с 2025 года переводятся в миллисекунды.

`metrics` — бесплатный архив фьючерсной статистики с нативным шагом 5 минут.
Для основного CSV из него выбирается только OI. В самих архивных частях могут
присутствовать ratios, но они не попадают в итоговый датасет. История OI доступна
не за все даты: отсутствующие архивы не заменяются нулями.

Funding загружается через `/fapi/v1/fundingRate`, с фактическим `fundingTime`,
включая миллисекунды. Период «каждые 8 часов» не предполагается автоматически.
Текущая funding-котировка не подменяет состоявшееся начисление.

В `coverage.json` сохраняются результаты каждой части:

- `complete` — часть прошла доступные проверки;
- `partial` — пустая либо с обнаруженными пропусками;
- `missing` — отсутствует бесплатный источник;
- `error` — ошибка загрузки или обработки.

`.csv.metadata.json` содержит число строк, диапазон, настройки объединения
и число строк без OI/funding. Пока источники не скачаны полностью, CSV тоже
может быть неполным. Наличие funding-записей само по себе не доказывает полноту
всех начислений.

Коды выхода: 0 — части прошли проверки; 2 — есть неполные/отсутствующие/ошибочные;
1 — ошибка параметров или файлов; 130 — прерывание.

## Остальные команды

```powershell
# Один CSV только со спотовыми свечами и покупками/продажами.
python candles.py --market spot --start 2025-01-01 --end 2025-01-03 --output data/spot_sample.csv

# Проверка небольшого полного набора.
python history.py --start 2025-01-01 --end 2025-01-02 --output data/check

# Текущий сбор spot + OI + начислений funding в CSV.
uv run parser.py --once
uv run parser.py
```

Для текущего сбора без uv: `python -m pip install "httpx>=0.27,<1"`.
Он сохраняет дневные CSV по таблицам; единый минутный исследовательский CSV
собирает `history.py`. Текущий сбор периодический, не полная лента сделок:
длительные остановки восполняются исторической загрузкой.
Прежние настройки `.env` и дополнительный режим ClickHouse сохранены;
в стандартных командах используется CSV.

Спотовые `aggTrades` доступны отдельной опцией `--datasets spot_trades` для
исследования volume profile. Они не скачиваются автоматически. Совместимые
старые дополнительные режимы также требуют явного `--datasets`; на состав
основного CSV это не влияет. Платные источники не подключены.

## Структура

```text
history.py                # Стандартная история и итоговый CSV
candles.py                # Отдельный CSV свечей
parser.py                 # Периодический текущий сбор
collectors/               # Загрузка, нормализация и объединение
tests/                    # Проверки корректности
data/                     # Исходные части, кэш и готовый CSV
trash/                    # Резервные копии прежнего кода
```

Дневные `.csv.gz` — внутренние части для возобновления и проверки, не результат,
который нужно вручную объединять. `--no-csv` отключает автоматическую сборку.
Даты/символы/источники меняйте через новую папку, кроме поддержанного сокращения
старого набора до согласованного состава.

```powershell
python -B -m unittest discover -s tests -v
python -B tests/smoke_online.py --output data/smoke_check
```
